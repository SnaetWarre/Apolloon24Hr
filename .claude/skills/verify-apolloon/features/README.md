# Operator workflows

| Screen | Drive | Verify |
| --- | --- | --- |
| Overzicht | Open a fresh database. Import or type another laptop's address. | The welcome screen moves to the overview once registrations appear. |
| Wachtrij | Search, check in, move, reorder, and hide runners. | Runner status and queue indices survive reload. |
| Timing | Start, hand off with Space or Enter, confirm a short lap, undo, finish, and resume. | Active runner, timestamps, and lap history agree. |
| Analyse and Tactiek | Change filters and chart ranges. Download exports and import a historical reference. | Exports match the stored race. Tactiek retains its reference on reload. |
| Beheer | Edit registrations, laps, labels, public settings, and backups. | The relevant server state changes and restores correctly. |
| Linked laptops | Link from either side, write through a follower, remove the leader, and restart. | The majority keeps confirmed laps and the returning laptop catches up. |
| Public displays | Open each display, change theme and zoom, and use F11. | Live race data appears and a browser on a failed laptop switches to a reachable peer. |
| Desktop | Start from a fresh profile, close during a race, and interrupt the window. | Only a confirmed close shuts down timing. The recovered window resumes at the same route. |
| Wrapped | Render a runner from SQLite and from a race workbook. | The expected story images and manifest are written. |
