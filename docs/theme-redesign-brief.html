What is actually there

Source audit · 8 routes

Your read is right from the operator's point of view. The workspaces are dark while the displays are bright. The code reaches that result in a way that makes a complete theme switch harder than it first appears.

Key finding: src/styles.css starts with a light :root palette. src/workspace.css then overrides the whole .app-root with a dark palette, and body:has(.app-root) turns the page background dark. Public display routes bypass that shell. There is no stored preference or toggle.

Operator routes

Start, Wachtrij, Timing, Analyse, Kobe's tactiek, and Beheer all use the dark shell. They share tokens, but also inherit many light-specific literal colors and dark-only exceptions.

Display routes

Binnenscherm uses a pale field with a blue header. Buitenscherm is a blue upper band and a light lower band. They are public, view-at-distance layouts with their own presentation needs.

Charts and boot

src/lib/chartPalette.ts fixes text, muted, and grid colors for dark charts. Chart datasets also contain literal colors. index.html has a light body before React starts, which can flash on dark loads.

The checked-out branch was main at 24ed577. An unrelated untracked notes.txt was left untouched. The proposal below has not been tested against a running event screen.

Visual direction

Choose with the preview below

The operator UI should feel like a calm race control desk. The public UI should read instantly across a room. Both should be recognizably Apolloon through blue, numerals, and clear race language, without forcing identical layouts.

Recommended starting point

Trackside

A compact, precise interface: blue identifies the current task and live race information; borders and alignment carry structure; rounded corners are restrained. Keep the current dense workspace, but make its rhythm and controls much more consistent. This direction is safest under event pressure.

Signature: one narrow live-race ribbon; quiet working areas; prominent timing action.

Bolder alternative

Clubhouse

More Apolloon blue and stronger section framing. Use a blue spine/header and squared surfaces for a distinctly club-owned feel. It could make Start and public moments more memorable. Guard against blue competing with warnings, buttons, and dense tables.

day canvasnight canvasday bluenight blue

Signature: a single stronger club-blue edge on the shell; minimal extra decoration elsewhere.

Design rules for either direction

Hierarchy and type

Use one dependable sans-serif family with tabular numerals for laps, times, ranks, and queue positions. Keep page titles compact and left aligned. Put the current runner and next action before secondary statistics. Avoid uppercase labels everywhere.

Surfaces and color

Give page, panel, inset, overlay, and public display distinct roles. Blue is navigation and primary action. Green, amber, and red mean state and risk. No color alone should convey queue position, health, or ranking.

Event ergonomics

Support tired volunteers, bright daylight, small laptop screens, and long sessions. Keep hit targets generous, readable at low brightness, and the main timing control immovable while the race updates.

Restraint

Do not turn every value into a card or pill. Prefer row alignment, short Dutch labels, and one meaningful emphasis per view. The visual upgrade should shorten scanning, not add ornament.

Theme behavior contract

Decision proposal

Visible control

Put a labeled Appearance button at the right end of TopNav, with Light, Dark, and System choices in an accessible menu or native select. On Start, which has no TopNav, place the same control in the home header. Show the active resolved choice; do not rely on a sun/moon icon alone.

Default and persistence

Default to System for a first visit. Save the explicit choice in browser localStorage on that device. Resolve System with prefers-color-scheme and update when the OS changes. Never write the preference into race data or synchronize it among laptops.

No first-paint flash

Read the safe stored value with a small early script in index.html before styles/app mount. Set data-theme on html, set appropriate color-scheme and page background, and handle blocked storage gracefully. React reads the same preference once and owns subsequent changes.

Public screens

Keep inside bright and outside blue/bright regardless of an operator laptop's theme. They are often opened on separate display devices and need stable distance readability. Give each display root complete, explicit color tokens and loading treatment. A separate venue-night option is a later, tested choice, never an accidental inheritance.

Scope and navigation

All six operator routes, connection/error/loading/not-found states, native controls, dialogs, menus, and charts must switch together without a reload or lost form state. The selected mode survives navigation and refresh. The display routes should never reveal an operator theme toolbar on the public picture.

Accessibility and safety

Keyboard reachable and visibly focused control, clear selected state, readable disabled controls, strong text and chart contrast, and no color-only health meaning. Theme changes must not trigger timing shortcuts, race mutations, chart data changes, or list reordering.

Implementation map

For the coding model

Theme state and first paint

  • Add a small client theme module/provider for system | light | dark and resolved mode.
  • Guard storage parsing, subscribe to OS preference only for System, and optionally listen for changes from another same-origin tab.
  • Initialize html[data-theme] before the bundle in index.html; keep the first paint consistent with React.
  • Keep preference local to the viewing browser, outside the server snapshot and SQLite replication.

CSS ownership

  • Consolidate semantic variables for operator light/dark near the stylesheet entry. Replace the unconditional dark overrides in workspace.css and the body:has(.app-root) background rule.
  • Scope public display values explicitly under .display-root, including loading and form controls, so operator theme cannot leak in.
  • Audit literal colors, logo inversion, modal backdrop, selected rows, badges, focus rings, controls, hover/disabled states, and responsive rules.
  • Delete superseded selectors as each route migrates. Avoid a new pile of late overrides.

Controls and components

  • Place a reusable labeled theme control in TopNav and RolePicker through App.tsx.
  • Keep navigation, search, dialogs, and timing focus behavior intact. A menu should close on Escape and return focus to its trigger.
  • Centralize genuine shared patterns: button, field, status, page heading, data row, and panel. Do not abstract every unique race layout.

Charts and brand

  • Replace the fixed workspaceChartPalette with a resolved semantic palette or read computed CSS variables when chart instances are created.
  • Update Analysis, tacticsCharts.tsx, and deepdiveCharts.tsx on theme change; destroy/recreate or update Chart.js instances cleanly.
  • Inspect every series, legend, tooltip, grid, empty chart, and hardcoded near-white line. Keep series identities stable across themes.
  • Check the Apolloon logo treatment in the nav, home, and displays; a CSS invert should never make the logo disappear on light.

Risks for the reviewer

A light theme can look finished while charts stay dark
Chart.js draws on canvas, so CSS variables do not recolor an existing chart. The implementation must resolve palette values, update or recreate instances on mode change, and inspect every chart in Analysis and Tactics.
A global theme can accidentally change public screens
The display routes do not use the operator shell. Their current colors partly inherit from the light root. Moving the palette to html[data-theme] without explicit display tokens can silently darken text, selects, badges, or loading screens on a projector.
The first frame and disconnected states can feel broken
The inline body in index.html is light and the operator shell appears later. The new bootstrap must set the initial page color before React. Error and loading branches in AppRoot still need the selected theme and a visible route back to work.
Redesign can regress event-speed actions
The timing view captures Space/Enter at window level, the board supports pointer and keyboard drag, and Admin keeps hidden sections mounted to protect unfinished forms. Preserve these exact behaviors while moving controls.
