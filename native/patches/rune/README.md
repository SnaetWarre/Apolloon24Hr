# Rune dependency

[revision](revision) pins the upstream Rune workspace. The build downloads that revision into the ignored `.rune` directory at the repository root and applies [apolloon.patch](apolloon.patch). Cargo compiles Rune and its platform dependencies from that prepared workspace. Browser builds, CI and npm commands prepare it automatically. For direct Cargo commands, run `bash native/scripts/prepare-rune.sh` first.

The patch preserves Apolloon's existing window controls, browser keyboard behavior, CPU rendering for rotated labels, and idle browser performance. The upstream reports cover [Linux titlebars](https://github.com/anomalyco/rune/issues/591), [window labels](https://github.com/anomalyco/rune/issues/1232), [keyboard activation](https://github.com/anomalyco/rune/issues/121), [rotated labels](https://github.com/anomalyco/rune/issues/1233), and [idle redraws](https://github.com/anomalyco/rune/issues/166). Rune now supplies the [WebGL2 handover and color fixes](https://github.com/anomalyco/rune/pull/1235).

## Update Rune

Confirmed handoff save answers request one draw admission by default. Only exact `APOLLOON_ACK_DRAW=0` disables it. The early successful partial outcome with a nonempty lap ID qualifies; state, long-poll, recovery, failed commands and animation wakes do not. A pending ACK first makes the next frame poll even when a resting timer already polled for it, then lets a waiting Metal redraw pass display-link pacing by advancing its last target to now. Naturally admitted frames consume it too. Concurrent ACKs and state updates coalesce into the same build; subsequent animation frames remain paced. Drawable acquisition, backpressure and failure handling are unchanged. Other platforms consume and trace the request at their next build without changing their pacing.

With `APOLLOON_LATENCY_TRACE=1`, `ack_draw_enqueue`, `ack_draw_build` and `ack_draw_present` carry the confirmed lap ID and their CPU timestamps. The last marker is emitted only after a successful present call returns, not on a skipped/acquire-failed frame. `save_ack_applied` identifies application of the outcome, including an outcome consumed by an already-running frame before its admission wake is handled. Join these with `build_begin`/`present_end` to locate the admitted frame and distinguish it from snapshot-labelled `applied`/`frame`. None is hardware presentation feedback. An unsuccessful build consumes its admission without rearming; existing surface/recovery handling remains responsible for later draws. Leave the independent state-admission experiment unset when measuring this default.

Native keyboard dispatch is immediate by default. Only `APOLLOON_IMMEDIATE_INPUT=0` restores the old queued-until-frame behavior; unset, empty and every other value keep immediate input on. After winit queues a non-synthetic keyboard event through the existing physical/logical routing, Rune drains the runtime input with zero animation time, without acquiring, encoding, submitting or presenting a drawable. This uses the same ordered queue, polling, focus/IME, repeat/release and handler/commit path as a normal frame, including earlier queued pointer or IME events. The drain takes ownership of the actions, so the next display-linked draw cannot handle them again. Clipboard and shell requests are flushed as for hidden input. Application handoff guards and outcomes are unchanged. Drawing and drawable backpressure remain display-link paced. Leave the urgent-frame switch unset when comparing default immediate input with the `=0` control.

With `APOLLOON_LATENCY_TRACE=1`, the `window_key` hook records Space/Enter at winit keyboard receipt, before queuing/dispatch, in both immediate-input arms (with repeat and control-focus fields). The benchmark joins it to the app `key` marker and injection timestamp: `Injection→winit receipt` measures delivery to winit, and `Receipt→key` measures Rune routing/queue wait. Missing boundaries remain N/A; these CPU timestamps are not scanout measurements. Early runtime work is outside the draw's runtime bracket and must not be inferred from that bracket alone.

`APOLLOON_URGENT_STATE_FRAME=1` enables a native state-delivery A/B experiment. Unset, empty, zero, values other than one, and malformed values keep existing behavior. Only a new authoritative display revision qualifies: the transport tracks the highest queued/applied revision per server epoch (retaining the latest 16 epochs so reconnects and restarts can have lower revisions). Duplicate, already-applied or older revisions, unchanged polls, unversioned/error responses, and recovery-only updates use the ordinary waker. All updates and command outcomes are still delivered. Setup, image loading, clock timers and animation ticks also use ordinary wakes. Distinct revisions queued before a frame coalesce into one admission: if Metal's display link would wait, that frame is admitted immediately with no presentation target and advances the link's last target to now. A naturally admitted frame also consumes the request. Later animation frames remain display-linked. Drawable acquisition and its existing failure/backpressure handling are unchanged. Other platforms accept the switch but do not bypass any pacing. There is no cooldown.

With `APOLLOON_LATENCY_TRACE=1`, a qualified transport wake emits `urgent_state_request`; an ordinary transport wake while the experiment is enabled emits `urgent_state_downgraded` with its `reason`, revision and change token. An actual Metal override emits `urgent_state_admission` between pacing markers through the existing asynchronous frame-stage trace. The benchmark's per-press `Urgent requests` column counts qualified requests for that lap; `Urgent (0/1)` identifies whether the first lap frame used the override, where zero also covers a naturally admitted frame or a non-Metal platform. This is not a GPU completion or pixel-time measurement. Leave both this switch and `APOLLOON_FRAME_LATENCY` unset for the unchanged baseline; vary one switch at a time for A/B runs.

The opt-in frame hook reports redraw entry, macOS display-link pacing, drawable acquisition, and runtime view/layout/paint separately. Acquisition includes surface reconfiguration and any GPU/drawable wait; runtime includes application polling. These CPU wall-time brackets do not measure physical scanout. Immediate keyboard dispatch runs the runtime before drawing; timer-only frames can also run it before acquisition. Other app/input redraws normally acquire first.

Within the runtime bracket, the same opt-in hook reports view/tree construction, commit, layout, text shaping/line breaking, cold system-font fallback, glyph preparation/rasterization, atlas allocation and paint preparation. Commit includes view/layout/text; paint includes glyph/atlas work. Nested phases overlap and must not be summed. No runtime hook is installed outside the current window's traced runtime call. Apolloon's Unix tracer also records the frame thread's CPU clock to distinguish computation from scheduler/blocking time. Image uploads and GPU pipeline preparation remain in the existing post-runtime upload/encode bracket.

Setup callbacks lend the window's own text system to public text measurement functions, just as view callbacks do. Apps can therefore prepare text/fallback fonts before the first frame without painting hidden content or populating a throwaway thread-local cache. Apolloon measures its existing handoff-success symbol during native setup; its system-font lookup then does not run on the first lap redraw. The symbol, style, fallback order and widget remain unchanged. Opt-in `text_warm_begin/end` events locate this startup work.

Native surfaces retain upstream AutoVsync presentation and desired frame latency (one on Windows, two elsewhere). For a macOS A/B experiment, `APOLLOON_FRAME_LATENCY=1` requests a maximum frame latency of one; leave it unset for the upstream default. Positive integers are accepted and Rune clamps them to `1..=2`; empty, zero or invalid values preserve the default. Upstream ignores this override on Windows, Linux and the web. On Metal, requests of one and two correspond to two and three drawables respectively. `RUNE_SURFACE_LOG=1` reports supported and selected modes and requested frame latency. This override does not change present mode or Rune's display-link admission policy. Apolloon's opt-in latency trace observes GPU frame build, submit and present boundaries through `App::on_frame_stage`; the hook does not schedule frames.

Ordinary native and browser GPU frames use Rune's retained damage renderer. Surfaces with `COPY_DST` receive a texture copy; others, including WebGL2, receive a full-screen textured-quad blit. The retained texture is sampled with `textureLoad`, without filtering or blending, through matching source and target view formats. Only Windows additionally supplies dirty presentation rectangles. Transparent clears, changed image/glyph atlases and renderer effects/layers/springs/surfaces retain whole-frame fallbacks. Resizing or replacing a surface discards its damage history.

Damage planning and retained/whole pixel equivalence tests run with `cargo test --manifest-path .rune/Cargo.toml -p rune --lib window::damage` after preparing Rune.

1. Check out the new Rune commit in a separate clone. Reapply the patch there, drop fixes that landed upstream, and save the remaining diff with `git diff --binary HEAD -- crates/rune crates/rune-text > /path/to/Apolloon24Hr/native/patches/rune/apolloon.patch` after marking new patch files with `git add -N`.
2. Put the new full commit SHA in `revision` and run `bash native/scripts/prepare-rune.sh` from Apolloon's root.
3. Run `cargo update --workspace --manifest-path native/Cargo.toml` to refresh the lockfile. Run `npm run build`, `npm run test:native`, and `npm run test:browser`.

GitHub downloads are pinned to a commit. Cargo's lockfile records the resolved crate versions.
