# Native replacement acceptance contract

The reference is the existing Electron application, including its server, browser/public displays, desktop integrations and packaged behavior. A renamed page or a summary in place of a feature does not count as implemented. The previous release remains available for reference in Git history.

## Appearance

Compare the same seeded data, viewport and theme in both applications. Preserve Geist, the Apolloon wordmark, icons, spacing, colors, tables, charts, dialogs, notices, keyboard focus and responsive layouts. Check light and dark at 1366×768 and 1920×1080. Public screens keep their distinct palettes and typography. Screenshot comparison must account for renderer font antialiasing without hiding layout differences.

## Linking improvement authorized by the user

Before a race, linking must be possible from either laptop with minimal operator travel. Show discovered computer names and clear connection progress. Merge the same registration once, retain different people even if bibs match, and preserve labels. Resolve the destination identically on both sides, including simultaneous clicks. An active first lap is a running race even when the completed-lap count is zero. Do not silently erase a real race or reinterpret an isolated racing laptop as an empty setup laptop. If practice data is replaced, keep a verified backup and say which data is retained. The current ten-lap practice threshold is reference behavior to evaluate explicitly, not silently copy as proof of a stopped race.

## Browser target

The same Rune UI must compile to WASM and work when guests browse to a laptop by IP and port over HTTP. Enable WebGL2 fallback and verify with WebGPU unavailable. Browser fetch uses the page origin; native-only storage/server/process code stays outside the WASM library. The local headless Chromium check passes with WebGPU unavailable: Rune hands over to WebGL2 (`web.handover.done`), renders, navigates to Timing and starts a runner through a real Rust server into SQLite. The browser smoke test also passed over plain HTTP on a non-loopback IPv4 address with Chromium reporting an insecure context. The browser timing and import check also passed with both WebGPU and WebGL2 disabled. Actual LAN-device and TV checks remain outstanding.

## Completion gates

- Every workflow above has a corresponding implementation and recorded native proof.
- Rust and reference backend return equivalent domain results for fixtures/actions; data survives restart and rollback.
- Native UI actions are exercised against real Rust servers, with persisted side effects checked separately.
- Three-laptop workflows and failure cases pass, including simultaneous linking, network partitions, restart and catch-up.
- Both themes and all public screens pass visual review against captured reference screenshots.
- Native platform packaging and desktop integrations are verified on their platforms.

The native desktop and WASM builds include the operator screens, public displays, CSV and Excel registration imports, lap corrections, backups and restore. The native suite exercises operator actions against a Rust HTTP server and checks the resulting SQLite state. The browser smoke test covers timing and registration import over HTTP with WebGPU disabled.

The Rust server can merge pre-race registrations in one transaction. It matches people by name, email and phone, preserves label memberships, and adds a runner without a number if their number is taken. It refuses to merge after the race starts, including during the first lap. With discovery enabled, Beheer shows nearby laptops and their race status. Existing linked databases remain protected against writes without the linked runtime.

Linked operation (`CLUSTER_ENABLED=true`, `native/src/cluster/`) ports the reference's majority voting, replicated SQL log, forwarded writes, joining and split handling. Peers talk JSON over HTTP instead of the reference's WebSocket, so Rust and TS laptops cannot share a group. In-process tests run three to four Rust servers on free ports with their own SQLite files. They cover linking from either side, with the same link direction on both sides and simultaneous presses, and the pre-race registration merge on join. They also cover follower writes forwarded to the leader and confirmed on a majority, leader loss and re-election, restart with log catch-up, and a cut-off leader that saves nothing and rejoins with the majority's data. Timing ownership, the Timing laptop going on alone by itself, split reconciliation with the lost-laps notice, and removing a lost laptop and linking a spare are tested too, as are the removed-laptop refusal and Opnieuw koppelen. A native UI test links two servers with Koppelen by address in Beheer › Systeem and leaves the group with Alleen verder werken. Backup restore and race clear replicate to the whole group. The leader first keeps a verified safety copy and reports where it is. Laptops that stop answering, and laptops that come back, are listed in Activiteit on every laptop. The leader stores the addresses and computer names that members announce over discovery, and the status lists laptops that linked by themselves. The native Systeem panel treats the `joining` and `resyncing` states as busy, as the reference does. The group clock offset is synced from the leader and kept across restarts, but it has only been exercised on one machine. A Mac and a Linux VPS merged pre-race registrations and replicated a follower write across SSH forwarding. Physical LAN and UDP discovery between machines remain open.

Race state, lap history, registrations, activity, and the CSV and JSON exports were compared against schema-17 reference databases. The Rust server also opened databases built from the original schema 13–17 SQL. It preserved the runner, queue position and lap on each. The schema 13–16 runs verified the original database copy, and tests cover preserving databases from before 4.0 and rolling back a failed repair. The Excel export matches the six reference sheets by value and formula. The full acceptance gates remain open. The workbook and SQLite Wrapped commands now start the Rust server. A headless Chromium comparison checked all four cards against the original using the same race data. The workbook export also regenerated a named runner’s cards and retained their send marker. Visual parity and physical LAN and display checks remain open. The Windows package workflow builds setup and drives installation, the real native window, firewall checks and uninstall in its runner.

An empty Overzicht offers import, discovered laptops with registrations, manual pairing by address, and the option to skip the welcome screen. Discovered laptops and manual addresses use the same confirmation as Beheer › Systeem. Manual entry opens and focuses the address field on Overzicht.
